# 06 — Release for the 2026/27 year: admissions, fees, hostel, postponement

**Time:** about 1 hour, including setup in the app. **When:** outside school
hours, before admissions open for 12 October 2026. **Where:** laptop, then server.

This release covers the admissions desks, the payment schedule (the awamu form),
hostel, required items, postponement and finishing. It adds database migrations
0045 to 0054, depending on how far the server already is. It needs **no new
Python packages and no new settings**. Guide 03 still does the deploy itself;
this guide covers what comes before and after it.

---

## A. On the laptop

**1. Run every test.** The last test drives one student end to end: admission,
records, finance, portal, invoices, results, both semesters and the year end.

```
$ cd backend
$ PSYCOPG_IMPL=python PYTHONPATH=venv/lib/python3.13/site-packages \
    /usr/bin/python3.13 manage.py test attendance --settings=edutrack.test_settings
```

Expect `Ran 732 tests … OK`. If anything fails, stop here.

**2. Commit everything, including the new files.** `git status` lists them under
"Untracked"; they have to be added, or the server gets migrations that point at
files it doesn't have:

```
backend/attendance/lifecycle.py
backend/attendance/management/commands/seed_payment_schedule.py
backend/attendance/migrations/0050_document_certificate_levels.py
backend/attendance/migrations/0051_item_checks_per_semester_and_holds.py
backend/attendance/migrations/0052_payment_schedules_and_hostel.py
backend/attendance/migrations/0053_postponement_and_completion.py
backend/attendance/migrations/0054_result_withholding.py
backend/attendance/test_authority_results.py
backend/attendance/test_end_to_end.py
backend/attendance/test_lifecycle.py
backend/attendance/test_payment_schedule.py
backend/templates/statement_print.html
ops/guides/06-release-2026-27.md
```

Push as usual (`git push origin master`).

**3. (Recommended) Rehearse the migrations on a copy of the real data.** The
deploy takes a safety copy anyway. The rehearsal finds a problem on your laptop
rather than on the live site. The copy holds students' personal data: keep it on
your laptop and delete it afterwards.

```
server$ (umask 077; sudo -u postgres pg_dump --format=custom edutrack_db > ~/rehearsal.dump)
laptop$ scp YOU@YOUR-SERVER-IP:rehearsal.dump ~/rehearsal.dump && ssh YOU@YOUR-SERVER-IP shred -u rehearsal.dump
laptop$ sudo -u postgres createdb -O raven edutrack_rehearsal
laptop$ pg_restore --no-owner -d edutrack_rehearsal ~/rehearsal.dump
laptop$ cd backend
laptop$ DB_NAME=edutrack_rehearsal PSYCOPG_IMPL=python PYTHONPATH=venv/lib/python3.13/site-packages \
          /usr/bin/python3.13 manage.py migrate
laptop$ DB_NAME=edutrack_rehearsal PSYCOPG_IMPL=python PYTHONPATH=venv/lib/python3.13/site-packages \
          /usr/bin/python3.13 manage.py seed_payment_schedule --year 2026/2027
laptop$ sudo -u postgres dropdb edutrack_rehearsal && shred -u ~/rehearsal.dump
```

`migrate` must finish without an error. `seed_payment_schedule` must print
`matches the form` nine times. If it says the schedule does not match the form,
the year's fee structure is missing or different: see B4.

## B. On the server

**1. See what this deploy will change.**

```
$ cd /var/www/edutrack/backend
$ sudo -u bphacoh venv/bin/python manage.py showmigrations attendance | tail -12
```

Every migration after the last `[X]` is applied by the deploy.

**2. Send a fresh backup off the server first.** This release is big.

```
$ sudo edutrack-backup
```

**3. Deploy** (guide 03):

```
$ sudo edutrack-deploy
```

It stops and prints the commands to go back if any step fails. See guide 03,
"Going back".

**4. Load the year's fees and instalment dates (once).**

First look in the app: Finance ▸ Fee Setup ▸ Fee Structure, year 2026/2027.

- **Empty:** load the published fee structure:
  ```
  $ sudo -u bphacoh venv/bin/python manage.py seed_fee_structure --year 2026/2027 --first-due 2026-10-19
  ```
- **Already filled in by the accountant:** do *not* run it. It would overwrite
  their amounts with the published ones.

Then load the instalment dates from the "Fomu ya tarehe za awamu za malipo":

```
$ sudo -u bphacoh venv/bin/python manage.py seed_payment_schedule --year 2026/2027
```

You should see nine lines ending `matches the form`. If the fee amounts differ
from the form, it saves nothing and says so.

## C. Setup in the app, before admissions open

In this order. Each office signs in with its own account.

| Who | Where | What |
|---|---|---|
| Principal / admin | User Accounts | Accounts for the **admission officer** and the **records officer** |
| Accountant | Fee Setup ▸ Charge Types | **TPH Book**, **Calculator**, **Rim Paper**: family *Other*, applies *On request*, the other-charges bank account |
| Accountant | Fee Setup ▸ Fee Structure | A rate for each of those at every level |
| Accountant | Fee Setup ▸ Payment Schedule | Check both schedules. **Confirm which "michango mingine" make up the new students' second instalment of 350,000.** The seed put research/field fees, the semester II national exam and graduation fees there |
| Admission officer | Admissions ▸ Window & ID numbers | The admission window for Semester 1 2026/27, the college ID format, and **Required items**: TPH Book, Calculator, Rim Paper (every semester) and **Insurance** billed under *Medical fees (Health Insurance)* (once a year) |
| Admission officer | Admissions ▸ My desk | If continuing students aren't queued at finance yet: **Send continuing students to finance** |
| Accountant | Each continuing student's application | Students already living in the hostel: press **Hostel**. Last year's hostel students aren't in the system, so this year it has to be done by hand |

## D. Check the live site (10 minutes)

Sign in as each office. Every page should open without an error message:

- **Admission officer:** My desk counts, New application, Window & ID numbers.
- **Records officer:** My desk shows only the records desks; Find a student works.
- **Accountant:** Payment Schedule subtotals, Items check, Hostel, and a student's
  statement with the *Tuition fee / Direct costs* buttons and one button for each
  other fee the student owes.
- **Principal:** Postpone & Finish opens; Semester Review opens.
- **Examination officer:** Results ▸ Results Summary for a semester and level.
- **A student** (a real one who agrees to help): sign in, My Profile shows their
  details and next of kin, Generate Invoice lists their payments, Request a
  Service shows Hostel and Postpone my studies.

## What staff will notice

- **Registering needs the first instalment paid.** This counts the charges ticked
  *blocks registration*, even before 19/10. Items (TPH, calculator, rim paper,
  insurance) never block anything. They are debts only.
- **Every office sees only its own desks.** Only the admission office and the
  Principal see the whole admissions queue.
- **Each other fee has its own invoice:** the supplementary exam, the special
  exam, a repeat module, the TPH book, and anything else raised on request. Each is
  offered only to a student billed for it.
- **Passwords last six months.** Every staff member's clock starts the first time
  they sign in after this deploy, so nobody is locked out on the day.
- **Postponement** is approved only by the Principal. It reverses that period's
  fees, and what the student paid is carried to their return as credit.
